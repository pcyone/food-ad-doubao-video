# 安装与使用说明

## 1. 适用环境

成片部分可运行在安装了 Node.js 和 FFmpeg 的 macOS 或 Linux 环境。

推荐版本：

- Codex Desktop 或 Codex CLI
- Node.js 20+
- FFmpeg 7+
- Python 3.11+
- zsh（Flow 辅助脚本使用）
- Docker Desktop（仅 Google Flow 自动生成需要）
- Google Chrome（仅 Google Flow 自动生成需要）

先检查基础工具：

```bash
node --version
ffmpeg -version
ffprobe -version
python3 --version
```

## 2. 安装 Skill

### 方法一：Git 克隆

```bash
skill_root="${CODEX_HOME:-$HOME/.codex}/skills"
mkdir -p "$skill_root"
git clone https://github.com/pcyone/food-ad-doubao-video.git \
  "$skill_root/food-ad-doubao-video"
```

如果已经安装过：

```bash
git -C "${CODEX_HOME:-$HOME/.codex}/skills/food-ad-doubao-video" pull --ff-only
```

### 方法二：从 ZIP 安装

解压后确保目录结构为：

```text
~/.codex/skills/food-ad-doubao-video/SKILL.md
```

不能多嵌套一层，例如下面这种结构是错误的：

```text
~/.codex/skills/food-ad-doubao-video/food-ad-doubao-video/SKILL.md
```

## 3. 配置豆包 TTS

复制示例文件到不会提交 Git 的私人位置：

```bash
cp .env.example /absolute/private/path/food-ad.env.local
```

填写以下变量：

```dotenv
DOUBAO_TTS_API_KEY=填写你的值
DOUBAO_TTS_RESOURCE_ID=填写你的值
DOUBAO_TTS_SPEAKER=填写你的值
DOUBAO_TTS_MODEL=可选
DOUBAO_TTS_SPEECH_RATE=-2
```

推荐通过环境变量告诉脚本配置文件位置：

```bash
export DOUBAO_TTS_ENV_FILE=/absolute/private/path/food-ad.env.local
```

也可以在每次渲染时传入：

```bash
node scripts/make-food-ad-video.mjs \
  --project /absolute/path/project \
  --env /absolute/private/path/food-ad.env.local
```

脚本只读取配置，不会在输出报告里写入具体凭据。

## 4. 配置 Google Flow 运行环境

如果只使用已有视频合成成片，可以跳过本节。

Flow 辅助流程依赖已经安装并完成授权的 `hbg-gemini-flow-suite`。设置其绝对路径：

```bash
export FOOD_AD_FLOW_SUITE_ROOT=/absolute/path/to/hbg-gemini-flow-suite
```

可选变量：

```bash
export FOOD_AD_FLOW_CONTAINER=gemini-flow-suite
export FOOD_AD_FLOW_CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
export FOOD_AD_FLOW_PROFILE="$HOME/.gemini-flow-suite/flow-chrome"
export FOOD_AD_FLOW_CDP_PORT=9323
export FOOD_AD_FLOW_BRIDGE_PORT=19323
```

Flow 登录状态、Chrome 授权资料和 Cookie 都应保留在本机，不要复制到 Skill 仓库。

## 5. 验证安装

确认入口文件存在：

```bash
test -f "${CODEX_HOME:-$HOME/.codex}/skills/food-ad-doubao-video/SKILL.md"
```

检查脚本语法：

```bash
skill_dir="${CODEX_HOME:-$HOME/.codex}/skills/food-ad-doubao-video"
node --check "$skill_dir/scripts/new-food-ad-project.mjs"
node --check "$skill_dir/scripts/make-food-ad-video.mjs"
node --check "$skill_dir/scripts/make-hero-extension.mjs"
zsh -n "$skill_dir/scripts/run-flow-project-task.zsh"
```

如果本机包含 Codex 的 `skill-creator` 校验器，还可以执行：

```bash
python3 "${CODEX_HOME:-$HOME/.codex}/skills/.system/skill-creator/scripts/quick_validate.py" \
  "$skill_dir"
```

## 6. 在 Codex 中调用

完整生成：

```text
使用 $food-ad-doubao-video，选择一道新菜，从写 Flow 提示词开始，生成约 40 秒竖屏广告，使用豆包连续口播，完成 MP4 和验收文件。
```

已有素材成片：

```text
使用 $food-ad-doubao-video，把我提供的多段竖屏菜品视频按顺序合并，使用最终口播稿生成豆包连续旁白，导出 40 秒成片并验收。
```

只检查已有视频：

```text
使用 $food-ad-doubao-video，仅对这个 MP4 重新执行 ffprobe、完整解码、黑场、音量和关键帧检查，不重新生成口播。
```

## 7. 手动创建项目

准备：

- `narration.txt`：最终口播稿
- 按顺序排列的视频文件
- 可选 `generation-audit.json`

初始化：

```bash
node "$skill_dir/scripts/new-food-ad-project.mjs" \
  --dish "菜品名" \
  --clips /absolute/path/scene01.mp4,/absolute/path/scene02.mp4 \
  --script /absolute/path/narration.txt \
  --out-dir /absolute/path/project \
  --duration 40 \
  --generation-audit /absolute/path/generation-audit.json
```

渲染：

```bash
node "$skill_dir/scripts/make-food-ad-video.mjs" \
  --project /absolute/path/project
```

输出包括：

- `audio/voiceover_doubao_raw.wav`
- `<菜品名>_高端美食广告_40s.mp4`
- `verification.json`
- `关键帧检查.jpg`

## 8. 常用参数

```text
--duration 40            目标时长
--ambient-volume 0.07    原视频氛围声基础音量
--voice-delay 0.25       旁白开始延迟
--speech-rate -2         豆包提供方语速参数
--crf 16                 H.264 画质参数
--preset slow            编码速度与压缩效率
--env /path/.env.local   豆包配置文件
```

## 9. Flow 项目提交与回收

标准 Flow 命令创建项目后，如果没有获得明确的 HTTP 200，可使用：

```bash
zsh "$skill_dir/scripts/run-flow-project-task.zsh" \
  submit PROJECT_ID /absolute/path/scene01.txt
```

如果已经提交成功，但本地下载失败：

```bash
zsh "$skill_dir/scripts/run-flow-project-task.zsh" \
  recover PROJECT_ID /absolute/path/scene01-output
```

恢复命令不会重新提交生成任务。

## 10. 常见问题

### 找不到豆包配置

确认 `DOUBAO_TTS_ENV_FILE` 指向存在的文件，且三个必填变量不为空。

### 旁白变速超出安全范围

当计算值低于 `0.88` 或高于 `1.18` 时，应该修改口播字数或调整目标时长，不要强行大幅变速。

### 视频不足目标时长

补充素材、缩短目标时长，或在得到允许并明确披露的情况下制作英雄画面延展。不能把本地延展写成 Flow 生成镜头。

### Flow 点数不足

停止反复尝试同一模型。最多检查一次真正更便宜的可用模型，然后选择等待点数、缩短视频或使用已披露的本地回退。

### Flow 已生成但本地没有文件

使用同一个项目 ID 执行 `recover`。不要先重新生成，以免重复扣除点数。

### 关键帧图为空或不完整

先用 `ffprobe` 检查成片真实时长和帧率，再确认视频可以完整解码。

## 11. 更新与备份

更新前可以先复制整个 Skill 目录作为备份。Git 安装可使用：

```bash
git -C "$skill_dir" pull --ff-only
```

如果希望停用 Skill，优先把目录移动到备份位置，而不是直接删除。
