# 40 秒竖屏美食广告完整生成视频中文版教程

本文介绍如何从一道菜开始，完成提示词、Google Flow 分段视频、豆包连续旁白、音画合成及验收。示例使用已经实际跑通的「东坡肉 40 秒竖屏广告」。

完整的东坡肉英文提示词保存在 [东坡肉 40 秒黄金样例](../references/dongpo-rou-golden-run.md)。

## 一、最终目标

默认交付规格：

- 菜品：任意中式或西式菜品
- 时长：40 秒
- 比例：9:16
- 分辨率：1080×1920
- 帧率：24fps
- 视频：H.264、yuv420p
- 音频：AAC、48kHz 双声道
- 旁白：豆包 TTS 一次性生成的连续中文口播
- 环境声：保留原视频烹饪声并压低
- 验收：`verification.json` 和 `关键帧检查.jpg`

40 秒不是硬性限制。其他时长也可以，但口播字数、分镜数量和素材总长度必须配套。

## 二、工作目录

建议为每道菜建立独立项目：

```text
food-ad-project/
├── scene-prompts/
│   ├── scene01.txt
│   ├── scene02.txt
│   ├── scene03.txt
│   ├── scene04.txt
│   └── scene05.txt
├── scene-checks/
├── narration.txt
├── generation-audit.json
├── clips.txt
├── project.json
├── audio/
├── verification.json
└── 关键帧检查.jpg
```

提示词、生成素材、口播稿和最终交付不要混在同一个无序目录中。

## 三、选择菜品和成片方向

适合 40 秒广告的菜品通常具备：

- 明确的原料状态
- 至少三次可见变化
- 有蒸汽、油脂、酱汁或切面等视觉亮点
- 有成品英雄镜头

东坡肉的变化链条很清楚：

```text
生五花肉 → 煎香 → 糖色和香料 → 小火慢煨 → 夹起滴汁 → 成品收束
```

不要选择在 40 秒内无法通过画面表达、又需要大量文字解释的主题。

## 四、建立连续性设定

先写一份“连续性圣经”，之后每段提示词都重复其中的关键内容。

东坡肉示例：

- 场景：私密、克制的中式餐厅厨房
- 台面：炭黑色石材
- 锅具：哑光黑色铸铁锅
- 主光：左上方暖色钨丝灯
- 补光：右侧柔和冷光
- 食材：同一批 4 厘米见方的带皮五花肉
- 肉块数量：固定五块，除非镜头动作明确改变数量
- 摄影：85–100mm 微距、浅景深、缓慢运动
- 色彩：深琥珀、红棕、炭黑、自然高光
- 声音：同步烹饪环境声，不生成对白和音乐

连续性设定最重要的不是文采，而是可重复：锅、台面、灯光方向、食材数量和尺寸必须清楚。

## 五、设计分镜

当 Flow 输出为每段 8 秒时，40 秒可以拆成五段。

| 段落 | 时间 | 核心动作 | 画面目的 | 旁白内容 |
|---|---:|---|---|---|
| 1 | 0–8 秒 | 五花肉入热锅煎香 | 建立原料与火候 | 好五花经得住火候 |
| 2 | 8–16 秒 | 冰糖上色、姜葱八角与绍酒入锅 | 展示香气和颜色变化 | 琥珀色与香料 |
| 3 | 16–24 秒 | 深色酱汁中慢煨 | 表达时间和耐心 | 小火慢煨、酱汁入味 |
| 4 | 24–32 秒 | 夹起肉块、浓汁滴落 | 展示软糯和肥瘦层次 | 软糯不散、浓汁回甜 |
| 5 | 32–40 秒 | 成品英雄镜头 | 品牌式收束 | 丰腴而不油腻 |

每段只安排一个主动作。八秒里同时要求煎、炒、炖、装盘，容易导致时间跳跃和食物变形。

## 六、编写 Flow 提示词

每段提示词建议按以下顺序组织：

1. 明确“一段连续的 8 秒竖屏广告镜头”。
2. 描述本段唯一主动作。
3. 重复场景、锅具、灯光和食材连续性。
4. 描述动作如何在八秒内自然变化。
5. 指定镜头、景深和摄像机运动。
6. 指定同步自然环境声。
7. 写完整负面约束。

通用结构：

```text
Create one continuous 8-second premium vertical food-commercial shot.

[同一场景、锅具、灯光、食材身份]

[本段唯一烹饪动作，以及动作在八秒内如何变化]

Photorealistic macro food cinematography, shallow depth of field,
[slow push-in / lateral slide / locked macro angle / subtle orbit], no cuts.

Natural synchronized cooking ambience only, no speech or music.
No text, captions, logos, packaging, unrelated person, duplication,
melting, morphing, broken food geometry, or sudden new props.
```

### 提示词检查清单

- 是否写明竖屏、时长和连续镜头？
- 是否重复了锅具、台面、灯光方向？
- 是否写明肉块或食材数量？
- 是否只有一个主动作？
- 是否避免不现实的时间跳跃？
- 是否写明无文字、无 Logo、无变形和无复制？

## 七、准备 Google Flow 环境

本 Skill 的 Flow 辅助流程基于已经授权的 `hbg-gemini-flow-suite`。

先设置路径：

```bash
export FOOD_AD_FLOW_SUITE_ROOT=/absolute/path/to/hbg-gemini-flow-suite
```

确认以下条件：

- Docker 容器 `gemini-flow-suite` 可以运行
- Chrome 授权资料存在
- Google Flow 登录没有过期
- 账号具有可用点数
- 输出目录可写

不得把 Cookie、账号令牌或浏览器资料复制到仓库。

## 八、逐段调用 Flow

在 Flow 套件目录中执行：

```bash
food_prompt=$(< /absolute/path/scene-prompts/scene01.txt)
./suite flow video t2v "$food_prompt" \
  --model veo-quality \
  --aspect 9:16 \
  --count 1 \
  --out-dir food-ads/dish-slug/scene01 \
  --json
```

建议：

- 每个场景独立项目
- 每次只请求一个候选
- 逐段执行，避免持久化浏览器资料锁冲突
- 每段成功下载并检查后再进行下一段

## 九、如何判断 Flow 是否真正提交

Flow 的页面出现项目、提示词或加载动画，不代表生成已经开始。

状态必须分开记录：

1. 项目已创建：尚未证明提交。
2. 提示词已写入：尚未证明提交。
3. 按钮已触发：仍需等待网络响应。
4. 生成接口返回 HTTP 200：可以记录为已提交。
5. 获得媒体 ID 或任务 ID：保存安全审计信息。
6. 文件下载并通过探测：本地素材可用。

如果标准命令创建了项目，却没有获得 HTTP 200，可使用已有项目 ID：

```bash
skill_dir="${CODEX_HOME:-$HOME/.codex}/skills/food-ad-doubao-video"

zsh "$skill_dir/scripts/run-flow-project-task.zsh" \
  submit PROJECT_ID /absolute/path/scene-prompts/scene01.txt
```

该脚本只识别唯一、可用的 `arrow_forward` 视频提交按钮，不点击模糊的通用 Create 按钮。

## 十、服务器成功、本地失败时的处理

如果已经看到 HTTP 200，但浏览器关闭、自动化异常或文件没有下载，不能直接重新生成。

使用原项目恢复：

```bash
zsh "$skill_dir/scripts/run-flow-project-task.zsh" \
  recover PROJECT_ID /absolute/path/scene01-output
```

恢复脚本会：

- 打开同一个 Flow 项目
- 观察媒体状态
- 查找成功的媒体 ID
- 下载一个有效的视频容器
- 不调用生成接口

服务器仍在处理中时，等待后再次恢复同一项目。

## 十一、Flow 点数耗尽时的回退

如果提交按钮明确显示点数不足：

1. 停止重复尝试同一模型。
2. 最多检查一次真正便宜的可用模型。
3. 若仍不可用，选择等待、缩短目标或复用已生成素材。
4. 任何本地回退都必须披露。

东坡肉实际运行中：

- 前四段由 Flow 真实生成，共 32 秒。
- 第五段因点数耗尽未提交。
- 从第四段约 6.2 秒处提取稳定英雄画面。
- 制作 8 秒缓慢推近收束镜头。
- 在 `generation-audit.json` 中明确记录。

生成英雄延展：

```bash
node "$skill_dir/scripts/make-hero-extension.mjs" \
  --source-video /absolute/path/scene04.mp4 \
  --at 6.2 \
  --out /absolute/path/scene05-hero-extension.mp4 \
  --duration 8
```

不能把这个文件写成“第五段 Flow 视频”。

## 十二、逐段素材验收

每段素材至少检查：

- 宽、高、帧率和时长
- 是否包含音频
- 能否完整解码
- 食物是否融化、复制或突然变形
- 道具、台面、锅具和灯光是否连续
- 画面中是否出现乱码、Logo 或包装
- 本段结束是否能接入下一段

示例探测：

```bash
ffprobe -v error \
  -show_entries stream=codec_type,codec_name,width,height,r_frame_rate \
  -show_entries format=duration \
  -of json /absolute/path/scene01.mp4
```

## 十三、编写最终口播稿

40 秒中文美食广告通常需要大约 140–180 个汉字，实际取决于音色、停顿和豆包语速设置。

东坡肉最终口播：

> 一块好五花，先要经得住火候的考验。热锅逼出油香，冰糖慢慢化开，给每一面染上琥珀色。姜葱、八角和绍酒入锅，香气随热雾层层升起。再交给时间，小火慢煨，让酱汁一点点收进肥瘦相间的纹理。揭盖的一刻，肉色红亮，轻轻一夹，软糯却不散。浓汁顺着边角缓缓落下，咸香里带着温润回甜。东坡肉，真正的丰腴，不是油腻，而是一口入口即化的从容。

写作原则：

- 顺序跟随画面，不抢跑
- 一次性写成完整口播
- 避免每八秒强行收尾
- 标点用于自然停顿
- 成片前确认是否锁稿

## 十四、准备生成审计文件


## 十五、配置豆包 TTS

创建私人配置文件：

```dotenv
DOUBAO_TTS_API_KEY=你的值
DOUBAO_TTS_RESOURCE_ID=你的值
DOUBAO_TTS_SPEAKER=你的值
DOUBAO_TTS_MODEL=可选
DOUBAO_TTS_SPEECH_RATE=-2
```

设置路径：

```bash
export DOUBAO_TTS_ENV_FILE=/absolute/private/path/food-ad.env.local
```

Skill 会一次性把完整口播发送给豆包，接收 PCM 流并转换为清理后的 48kHz WAV。


初始化脚本生成：

- `narration.txt`
- `clips.txt`
- `project.json`
- `run-command.txt`

## 十七、生成豆包连续旁白并合成

```bash
node "$skill_dir/scripts/make-food-ad-video.mjs" \
  --project /absolute/path/dong-po-rou-project
```

内部过程：

1. 读取最终口播和豆包配置。
2. 一次性生成连续 PCM 音频。
3. 转为 48kHz WAV。
4. 去掉开头、结尾多余静音。
5. 测量旁白真实时长。
6. 计算轻微变速比例。
7. 统一所有画面为 1080×1920、24fps。
8. 把有声素材的原声压低，无声素材补静音。
9. 拼接画面和氛围声。
10. 旁白做响度统一并延迟 0.25 秒进入。
11. 混合、限幅并导出 H.264/AAC MP4。
12. 自动执行完整解码、黑场和音量检查。

## 十八、旁白时长对齐

公式：

```text
tempo = 原始旁白时长 ÷（目标时长 - 旁白延迟）
```

东坡肉实际数据：

```text
原始旁白：40.059458 秒
目标时长：40 秒
旁白延迟：0.25 秒
有效窗口：39.75 秒
tempo：1.007785
```

只加速约 0.8%，基本不会改变音色。

允许范围：

```text
0.88 ≤ tempo ≤ 1.18
```

超出范围时修改文案或目标时长。

## 十九、音画合成参数

画面：

```text
scale=1080:1920:force_original_aspect_ratio=increase
crop=1080:1920
fps=24
setsar=1
```

音频：

- 原始氛围声基础音量：`0.07`
- 旁白响度目标：约 `-16 LUFS`
- 旁白开始延迟：`0.25 秒`
- 最终峰值限幅：避免削波

导出：

```text
H.264 High Profile
yuv420p
CRF 16
preset slow
AAC 192kbps
48kHz stereo
faststart
```

## 二十、自动验收

脚本自动输出 `verification.json`，包含：

- 菜品名
- 输入素材及每段时长
- 是否含音频
- 原始旁白时长
- 变速比例
- 成片时长和文件大小
- 分辨率、帧率和总帧数
- 音频编码、采样率和声道
- 完整解码结果
- 0.5 秒以上黑场数量
- 平均音量和最大音量
- Flow 生成与回退审计

关键帧图默认抽取：

- 约 1 秒
- 25% 时长
- 50% 时长
- 75% 时长
- 结束前约 1 秒

东坡肉验收结果：

```text
时长：40.000000 秒
分辨率：1080×1920
帧率：24fps
总帧数：960
视频：H.264
音频：AAC 48kHz 双声道
平均音量：-20.4dB
峰值：-5.8dB
完整解码：通过
持续 0.5 秒以上黑场：0
```

## 二十一、只重新检查已有 MP4

不重新调用豆包、不重新渲染：

```bash
node "$skill_dir/scripts/make-food-ad-video.mjs" \
  --verify-existing /absolute/path/final.mp4 \
  --out-dir /absolute/path/verification-output
```

该模式会重新生成 `verification.json` 和 `关键帧检查.jpg`。

## 二十二、最终人工验收

自动检查不能替代人工看图和听声音。

交付前确认：

- 关键帧顺序符合烹饪逻辑
- 没有错误裁切或黑边
- 食材没有明显变形、复制或融化
- 第一个镜头能快速建立菜品
- 最后一个镜头具有成品收束感
- 旁白没有断句、爆音或机械变速感
- 氛围声可感知但不压过口播
- 所有本地回退均已披露

## 二十三、交付清单

建议交付：

```text
菜品名_高端美食广告_40s.mp4
verification.json
关键帧检查.jpg
最终口播稿.txt
提示词与口播稿.zip
```

在交付说明中写明：

- 成片规格
- 豆包旁白原始时长和变速比例
- Flow 真实生成段数
- 是否使用本地回退
- 自动与人工验收是否通过

完成以上步骤后，这条视频才算真正“生成完成”，而不只是得到一个 MP4 文件。
